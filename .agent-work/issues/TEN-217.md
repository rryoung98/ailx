# TEN-217 — [P1] finishConnect casts an unvalidated 200 body, so a successful model connection can be shown as not connected
status: Backlog
url: https://linear.app/tenken/issue/TEN-217/p1-finishconnect-casts-an-unvalidated-200-body-so-a-successful-model

**What breaks.** The OAuth callback path skips the body reader the rest of the module uses. A 200 whose body omits `connected` ends the round trip with no error, clears the endpoint slot and leaves the Start gate shut.

**Evidence.**
`apps/web/lib/data/modelGateway.ts:279-284`:

```ts
if (status !== 200 || typeof body !== "object" || body === null) {
  return { ok: false, message: callbackFailureCopy(status) };
}
return { ok: true, status: body as KeyStatus };
```

`readStatusBody()` (`modelGateway.ts:60-80`) exists for exactly this and is used by `readKeyStatus` and `disconnectKey`, but not here. At the call site `applyStatus` clears the endpoint slot when `connected` is falsy (`features/exam/ConnectPanel.tsx:135-137`) and the panel renders on `status?.connected === true` (`:304`). The same cast lets a non-fingerprint string reach `connectedCopy(status?.fingerprint)` (`:326`, `:82-84`). `apps/web/test/modelGateway.test.ts` covers `readStatusBody` and the refusal copies, never a 200 with a wrong shape on the callback.

**Blast radius.** Every hosted candidate connecting a model. They sign in at OpenRouter, come back, and are told they are not connected, with no error and Start disabled.

**Fixed when.** `finishConnect` routes the body through `readStatusBody`, and a test asserts a 200 with `{}` becomes a refusal message, not a silent disconnect.
