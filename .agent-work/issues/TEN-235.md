# TEN-235 — [P2] The share-to-wall button has no timeout and no unmount guard, and its URL is hardcoded in two files
status: Backlog
url: https://linear.app/tenken/issue/TEN-235/p2-the-share-to-wall-button-has-no-timeout-and-no-unmount-guard-and

**What breaks.** A 1.3 MB POST to a hardcoded third-party demo host with no deadline and no cleanup. If the host stalls, the button stays on Sharing... for ever. A per-day rate limit is reported as try again later, which is wrong by roughly a day.

**Evidence.**
`apps/web/app/report/page.tsx:73` `const GALLERY_API = "https://ailx-shared-demo.vercel.app/api/gallery";` and the same literal at `apps/web/app/wall/page.tsx:19`, neither through `apiBase()` or the route manifest. The handler at `app/report/page.tsx:89-113` has no `AbortSignal`, no unmount flag, and posts up to three recompressed data URIs (`:96`, 440 KB each). The proxy's limit is per day: `services/openrouter-proxy/api/gallery/index.js:44-46`.

**Blast radius.** T4 candidates on the report, on the request most likely to stall on mobile.

**Fixed when.** One constant for the demo gallery base, a request timeout, an unmount guard, and a distinct sentence for a 413 or 429.
