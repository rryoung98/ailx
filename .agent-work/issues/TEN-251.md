# TEN-251 — [P2] No database backup or PITR is provisioned or stated anywhere
status: Backlog
url: https://linear.app/tenken/issue/TEN-251/p2-no-database-backup-or-pitr-is-provisioned-or-stated-anywhere

**What breaks.** The store is append-only and is the whole product. There is no database resource in Terraform at all, and no backup, PITR or RPO statement anywhere in the repo. Migrations are forward-only with `max_retries = 0`, so a bad migration has no documented recovery path.

**Evidence.**

* `infra/terraform/*.tf` declares no database resource; the database is the existing Neon Postgres (README section 7).
* `grep -rn 'PITR\|point-in-time\|backup' README.md docs/ infra/` returns two unrelated hits.
* `infra/terraform/judging.tf` and the migrate job use `max_retries = 0`.
* README section 7 already records that a future Cloud SQL move needs a `pg_dump` taken during a write freeze, because a snapshot taken while writes continue would silently drop rows. Nothing states the RPO today.

**Blast radius.** Total loss of every score of record, every judgment and every credential, with no stated recovery point.

**How we know it is fixed.** The Neon branch/PITR retention window is written down with an RPO, a restore is rehearsed once, and the runbook is in the README.
