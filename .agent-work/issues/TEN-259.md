# TEN-259 — [P2] Clerk tokens are verified with no authorizedParties, so azp is never checked
status: Backlog
url: https://linear.app/tenken/issue/TEN-259/p2-clerk-tokens-are-verified-with-no-authorizedparties-so-azp-is-never

**What breaks.** `verifyToken` is called with `secretKey` only. The `azp` claim is never checked, so any token minted by the same Clerk instance for any front end is accepted by this API. The service already knows the list it should pass.

**Evidence.**

* `packages/backend/src/clerk.ts:20-24`: `const payload = await verifyToken(auth.slice("Bearer ".length), { secretKey: this.secretKey });`
* Clerk's own guidance is to pass `authorizedParties` so a token issued for another front end cannot be replayed.
* The allowlist is already available as `AILX_ALLOWED_ORIGINS` / `allowed_origins` in `infra/terraform`.
* Today the same Clerk instance backs the public frontend and both staging deployments, and README section 7 records it is a DEVELOPMENT instance repurposed from another product.

**Blast radius.** Only matters once a second app shares the Clerk instance, which is exactly what a repurposed development instance means today.

**How we know it is fixed.** `verifyToken` receives `authorizedParties` built from `AILX_ALLOWED_ORIGINS`, and a test asserts a token with a foreign `azp` is refused.

*Filed from a read-only review of* `ailx-backend` *@* `72db4e6` *(main), 2026-09-07.*
