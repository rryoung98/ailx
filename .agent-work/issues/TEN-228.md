# TEN-228 — [P1] 'use server' is banned in prose only, so a server action in a hosted page would be an unguarded public endpoint
status: Backlog
url: https://linear.app/tenken/issue/TEN-228/p1-use-server-is-banned-in-prose-only-so-a-server-action-in-a-hosted

**What breaks.** FRONTEND.md bans server actions, and no test enforces it. The frontend-only gate looks for `apps/*/app/api/**` and route file names, so a `'use server'` block inside any of the hosted `page.api.tsx` files compiles into a public POST endpoint in this repo, which is exactly what the repository split forbids, with the suite green.

**Evidence.**
`rg -n 'use server' --glob '!node_modules' -l` returns `FRONTEND.md` only, so the rule exists solely as prose. The gate's route checks in `packages/core/test/frontendOnly.test.ts` match `apps/*/app/api/**` and `route.(api.)?tsx?` file names; neither pattern can see a directive inside a page component. Related gap in the same test: the route regex misses `route.js` and `route.mjs` outside `app/api`.

**Blast radius.** The one-route-handler invariant in AGENTS.md, which is the reason a reviewer sees any new server surface. A server action is a handler with no file name to catch it.

**Fixed when.** The gate greps every source file under `apps/*/app/**` for a `'use server'` directive and fails, with a fixture proving the failure.
