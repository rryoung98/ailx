# TEN-258 — [P2] funnel_events is anonymous-writable with three indexes and no retention
status: Backlog
url: https://linear.app/tenken/issue/TEN-258/p2-funnel-events-is-anonymous-writable-with-three-indexes-and-no

**What breaks.** The funnel sink is the only route a stranger can write. The rate limit is per instance, so the real ceiling is multiplied by `max_instances`. Worst case is roughly 300/min x 20 rows x 4 instances, about 34M rows a day, into a table with three indexes, no partitioning and no retention job.

**Evidence.**

* `services/api/src/rateLimit.ts` `FUNNEL_SHARED_RATE_LIMIT = 300/min`, per instance and in-process (README section 2 states this).
* `infra/terraform/variables.tf` `max_instances = 4`.
* The per-address limit is inert because `AILX_TRUST_PROXY` is set nowhere in `infra/terraform` (`clientAddress` returns null without it).
* `db/schema.sql`: `funnel_events` carries three indexes and no partitioning; there is no retention job anywhere in the repo.
* Verified CLEAN: the step name IS a real Postgres CHECK constraint as the README claims, the insert is idempotent (`funnel_events_once`), and the row carries no IP, user agent, URL, referrer, account id or attempt id.

**Blast radius.** Storage and index bloat on the one table a stranger writes, plus autovacuum load on the shared database.

**How we know it is fixed.** A retention or partition policy exists for `funnel_events`, and the ceiling is stated as a global number rather than a per-instance one.
