# TEN-197 — [P2] A store with the funnel table missing is typed as unconfigured rather than empty
status: Backlog
url: https://linear.app/tenken/issue/TEN-197/p2-a-store-with-the-funnel-table-missing-is-typed-as-unconfigured

**What breaks.** The five standing kinds are meant to be exhaustive and distinct: `unconfigured` means nobody pointed this deploy at a source and the fix is an environment variable. `app/(dashboard)/people/page.tsx` `unread()` returns `kind: "unconfigured"` for a store that IS configured and simply predates the funnel migration. That is a configured source reported as an unset variable.

**Evidence.** `app/(dashboard)/people/page.tsx`, function `unread()`, returning `{ kind: "unconfigured", reason: ... }` from a branch reached only when the database read succeeded. `lib/standing.ts` maps `unconfigured` to the label "no source configured" and to the dashed mark.

**Blast radius.** Small today, because `BrowserPanel` renders only the reason text, which is accurate. It grows the moment anything summarises that source into a standing badge or an attention row, which is what `lib/standing.ts` exists for.

**How to know it is fixed.** The state has its own kind or reuses `empty`, and no code path can label a reachable store "no source configured". A test that reads a store without `funnel_events` asserts the kind.
