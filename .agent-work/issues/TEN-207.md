# TEN-207 — [P0] A failed runner chunk import silently swaps a demo placeholder into a real scored track
status: Backlog
url: https://linear.app/tenken/issue/TEN-207/p0-a-failed-runner-chunk-import-silently-swaps-a-demo-placeholder-into

**What breaks.** `loadTrackModule` catches a failed dynamic import and returns `PlaceholderRunner` with `placeholder: true`. The exam page never reads that flag, so a 404 on a hashed chunk (a tab open across a deploy), a dropped connection or a blocking extension replaces a real timed track with four grey demo buttons, and the `{demo:true}` artifact is scored as the candidate's work.

**Evidence.**
`apps/web/lib/instrument/registry.ts:52-61`:

```ts
  } catch {
    // fall through
  }
  return { Runner: PlaceholderRunner, placeholder: true };
```

`apps/web/app/exam/page.tsx:1009` renders `<mod.Runner {...uiProps} />` unconditionally; grep finds no consumer of `mod.placeholder` outside tests. `apps/web/components/PlaceholderRunner.tsx:51` submits `props.onComplete({ demo: true, trackId, response, interactions })`.

**Blast radius.** Any candidate whose browser fails one dynamic import mid-sitting. The result is a void or zero score presented as a real one. This is the same class the deck guard already refuses (`DeckMismatchError`, `persistence.ts:296`).

**Fixed when.** The exam page refuses to mount a `placeholder: true` module for a real attempt and shows the deck-error panel with a retry (`page.tsx:989`), plus a test that makes `loadTrackModule` fail and asserts no placeholder is mounted on a scored track.
