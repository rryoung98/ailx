# TEN-213 — [P1] The server-rendered share, verify and card reads have no timeout, so a slow exam service becomes a platform 504
status: Backlog
url: https://linear.app/tenken/issue/TEN-213/p1-the-server-rendered-share-verify-and-card-reads-have-no-timeout-so

**What breaks.** The three server reads on the render path have no deadline. Their `catch` fallbacks only run on a rejection, so a hang runs out the serverless function budget instead of rendering the honest sentence they were written for.

**Evidence.**
`apps/web/app/s/[token]/page.api.tsx:28-39`:

```ts
const res = await fetch(`${await serverApiBase()}${apiPath("shareView", { token })}`, { cache: "no-store" });
```

`apps/web/app/verify/[code]/page.api.tsx:33-43` and `apps/web/app/s/[token]/card.png/route.api.ts` are identical in shape, and all three are `export const dynamic = "force-dynamic"`. The comment at `verify/[code]/page.api.tsx:38-42` states the intended behaviour (`Unreachable service: the PAGE says so out loud`), which a hang never reaches.

**Blast radius.** Credential verification is the one surface a stranger acts on (docs/CREDENTIAL.md) and share unfurls are the growth loop. Both fail hardest exactly when the service is under load: a recruiter gets the platform 504, and the OG card breaks in every social cache that fetched during the window.

**Fixed when.** All three server reads carry an explicit `AbortSignal.timeout` inside the platform function limit, and a test with a never-settling fetch asserts the not-found metadata or 404 card returns within the budget.
