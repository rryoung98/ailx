# TEN-186 — [P1] A Clerk outage renders as not on the allowlist, which points the reader at the wrong fix
status: Backlog
url: https://linear.app/tenken/issue/TEN-186/p1-a-clerk-outage-renders-as-not-on-the-allowlist-which-points-the

**What breaks.** `middleware.ts:38-41` catches a failed Clerk lookup and returns `null`; `:47` feeds that to `isAllowedEmail`, which cannot tell "no email" from "Clerk did not answer", and the request is rewritten to `/denied`. `lib/server/admin.ts:56-60` does the same and returns a 403 reading "this account is not on the allowlist".

**Evidence.** `middleware.ts:38-48`, `lib/server/admin.ts:50-60`.

**Blast radius.** Every admin at once during any Clerk incident, and the recovery action the copy asks for (edit `ADMIN_ALLOWED_EMAILS`) cannot help. Failing closed is right. Naming the wrong cause is the defect, and it is the same error this repo refuses everywhere else: an unreadable source must say it is unreadable.

**How to know it is fixed.** A third state for unreachable with its own sentence. A throwing Clerk client produces it; an allowlist miss still produces denied.
