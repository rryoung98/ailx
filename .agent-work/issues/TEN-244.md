# TEN-244 — [P1] GET /v1/aggregates and GET /v1/gallery scan whole tables on every anonymous request and carry no cache header
status: Backlog
url: https://linear.app/tenken/issue/TEN-244/p1-get-v1aggregates-and-get-v1gallery-scan-whole-tables-on-every

**What breaks.** The two public reads are unbounded full-table work on routes a stranger may call in a loop. `/v1/aggregates` selects EVERY `responses` row whose payload type is `attempt_started` or `track_scored`, with no LIMIT and no time window, sorts them, ships them to Node and JSON.parses each one, plus three more full-table aggregations. `/v1/gallery` runs about eight queries per page view, six of them full scans. Neither carries `Cache-Control` or `ETag`, so every page view costs a container and a pool client.

**Evidence.**

* `packages/backend/src/aggregates.ts:41` `SELECT attempt_id, payload FROM responses WHERE payload->>'type' = ANY($1) ORDER BY attempt_id, seq`. No LIMIT. Live plan: `Seq Scan on responses ... Filter: ((payload ->> 'type') = ANY (...))` then a Sort. No index exists on `(payload->>'type')`.
* Same handler: `aggregates.ts:97` explodes every `attempt_decks` row, `:123` groups all of `attempts` by week, `:140` runs three `count(*)`.
* MEASURED on a PGlite replay of `db/migrations` (40 log rows per attempt):

| attempts | responses rows | rows into Node | query time |
| -- | -- | -- | -- |
| 2,000 | 80,000 | 4,000 | 28 ms |
| 12,000 | 480,000 | 24,000 | 180 ms |

Linear. 50,000 attempts projects to about 750 ms and 100,000 rows materialised per anonymous request.

* Gallery: `packages/backend/src/gallery.ts:237` listing, `:244` count, `:274` publishedCount, `:314` a `GROUP BY s.payload->'playerType'->>'code'` that no index can serve, `:345` a loop of four axis queries. `packages/contract/src/gallery.ts:217` caps `offset` at `Number.MAX_SAFE_INTEGER`.
* MEASURED live: `/v1/gallery` 124 ms and `/v1/aggregates` 184 ms warm median, with only `vary: Origin` and no `Cache-Control` or `ETag`. Cold start for `/livez` was 7628 ms with `min_instances = 0`.
* The only ceiling is `PUBLIC_READ_SHARED_RATE_LIMIT = 600/min` per instance (`services/api/src/rateLimit.ts`), which is 10 requests/second against a 3-connection pool. The per-address limit is inert because `AILX_TRUST_PROXY` is set nowhere in `infra/terraform`.

**Blast radius.** Anonymous, no account needed. The wall and the world page are the growth surfaces, so this is the route real traffic hits first, and it shares the pool with every sitting.

**How we know it is fixed.** The aggregate is materialised or cached with a validator, `offset` is capped at a real page depth, the facets are one query, and the plan for both routes contains no `Seq Scan on responses` or `share_links`.
