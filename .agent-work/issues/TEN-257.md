# TEN-257 — [P2] The T1 GitHub export has no request timeout and leaves an empty repo when it hangs
status: Backlog
url: https://linear.app/tenken/issue/TEN-257/p2-the-t1-github-export-has-no-request-timeout-and-leaves-an-empty

**What breaks.** The GitHub artifact export uses bare `fetch` with no `AbortController` anywhere, uploads up to 500 blobs in one request, and creates the repository FIRST with no compensating delete. A hang or a partial failure leaves an empty repository on the candidate's own GitHub account with no cleanup, and the export route has no rate limit.

**Evidence.**

* `packages/backend/src/t1/github.ts:206-224`: bare `fetch`, no `AbortController`. `grep -n AbortController packages/backend/src/t1/github.ts` returns nothing.
* Contrast `packages/backend/src/judging/model.ts:285`, which does use one, so the pattern is known in this repo.
* `packages/backend/src/t1/github.ts:499-520` creates the repo before any blob is uploaded; there is no delete on failure.
* `packages/contract/src/t1.ts` `T1_LIMITS.maxFiles = 500`.
* The route carries no rate limit (see the authenticated rate-limit finding).

**Blast radius.** A candidate's own GitHub account gets an empty repo, and the request occupies an instance until the socket dies.

**How we know it is fixed.** Every GitHub call carries an `AbortController` with a budget, a failed export deletes the repo it created or creates it last, and a test with a hanging server shows the handler returning inside the budget.

*Filed from a read-only review of* `ailx-backend` *@* `72db4e6` *(main), 2026-09-07.*
