# TEN-214 — [P1] An identity that never resolves has no bound, so every service page loads for ever with no error
status: Backlog
url: https://linear.app/tenken/issue/TEN-214/p1-an-identity-that-never-resolves-has-no-bound-so-every-service-page

**What breaks.** The identity store starts at PENDING and only the Clerk bridge moves it. Every reader treats pending as `wait indefinitely`, with no deadline and no fallback. If the Clerk script is blocked by an extension, a CSP or a failed CDN, `isSignedIn` stays undefined and no read ever fires.

**Evidence.**
`apps/web/lib/auth/identityState.ts:78` `let current: Identity = PENDING;`, published only from `lib/auth/ClerkTokenBridge.tsx:39,47`, which publishes `pending` whenever `isSignedIn === undefined` (`:36-45`). Readers: `lib/data/serviceFetch.ts:270` `enabled: path !== null && identityStatus !== "pending"`, and `features/report/useScoresOfRecord.ts:77` `if (!live || identityStatus === "pending") return;`. The report turns it into copy with no way out, `features/report/reportGate.ts:114-121` returns `cta: null` while `reading`. `readIdentity()` short-circuits only for builds with NO Clerk (`identityState.ts:105`), which is the case that is already fine. `apps/web/test/identityState.test.ts` and `serviceFetch.test.tsx:335-369` pin the resolution path, not the never-resolves path.

**Blast radius.** Every service-reading page on any Clerk deployment, for any candidate with an ad blocker or a corporate proxy. A finished candidate is parked on `Checking what the exam service has issued for this sitting...` with no button.

**Fixed when.** `pending` gets a deadline, after which the store publishes anonymous or asserted and the pages ask with what the browser has. A test mounts /report with Clerk enabled, never calls `publishIdentity`, and asserts a rendered sentence and a control instead of a spinner.
