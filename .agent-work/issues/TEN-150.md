# TEN-150 — funnel_events.identified is false on every row by construction, including signed_in — decide whether the column should exist
status: Backlog
url: https://linear.app/tenken/issue/TEN-150/funnel-eventsidentified-is-false-on-every-row-by-construction

Checked in the staging store 2026-09-05. `funnel_events.identified` is `false` on every row ever
written, including the `signed_in` row emitted tonight the moment an account arrived.

It cannot be anything else. `apps/web/lib/data/funnel.ts` `browserSend()` posts with
`credentials: "omit"` and no identity header, deliberately ("Anonymous by construction"), which
is the promise docs/KPI.md makes. So the service has nothing to set the column from, and the
column is dead weight that reads as a fact.

Two ways out, and it needs a decision rather than a patch:

* delete the column and say in docs/KPI.md that the funnel cannot separate signed-in traffic; or
* keep it and define exactly what would set it (e.g. the service marking a batch that arrived
  with a valid bearer, which would break the anonymity promise and must be argued for).

Either way `signed_in` is currently a step that records that SOMEBODY signed in during a
session, on a row that says nobody was identified. As long as both exist unexplained, an
analytics reader will draw the wrong conclusion.
