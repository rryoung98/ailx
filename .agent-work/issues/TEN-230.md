# TEN-230 — [P2] created.attempt is read with no shape check, so a 200 with an unknown body shows a raw TypeError to the candidate
status: Backlog
url: https://linear.app/tenken/issue/TEN-230/p2-createdattempt-is-read-with-no-shape-check-so-a-200-with-an-unknown

**What breaks.** Both attempt-creation paths cast the response. A 200 without `attempt` throws `Cannot read properties of undefined`, and on the start path that string is rendered to the candidate. If `attempt.id` is present but not a non-empty string, every later sync pass throws in `apiPath` and no row is ever appended.

**Evidence.**
`apps/web/lib/data/persistence.ts:219` and `:351`:

```ts
state.serverAttemptId = (created.attempt as { id: string }).id;
```

`postJson` checks only `res.ok` (`:161-163`). `packages/contract/src/routes.ts:220-224` throws `route appendResponse: missing parameter "id"`. `apps/web/test/persistence.test.ts` stubs only the correct shape (lines 50, 347). Contrast `serviceFetch.ts:190-198`, which validates when a schema exists.

**Blast radius.** Hosted starts against a service that is up but answering a shape this build does not know: version skew, an interception page, a 200 error envelope.

**Fixed when.** A shape check yields a typed failure, with a test that uses `{}` as the create body.
