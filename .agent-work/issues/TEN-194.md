# TEN-194 — [P2] A row shaping error is reported as a database refusal
status: Backlog
url: https://linear.app/tenken/issue/TEN-194/p2-a-row-shaping-error-is-reported-as-a-database-refusal

**What breaks.** `lib/server/db.ts:70-80` runs `result.rows.map(shape)` inside the same `try` as the SQL, so a throw from `toCount` (`:110`) or `toDay` is caught by the database catch at `:82` and rendered as "The exam database refused the query". The database was fine; the shaper was wrong.

**Evidence.** `lib/server/db.ts:66-88`. A renamed column or a NULL count produces this today.

**Blast radius.** Any panel. In a repo whose central rule is that a sentence on screen must be true, this is a wrong sentence with a confident diagnosis attached, and it sends the reader to the store instead of to the code.

**How to know it is fixed.** Shape outside the transaction try, or tag the two failures apart. A shaper that throws produces a reason naming a shaping fault.
