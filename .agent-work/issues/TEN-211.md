# TEN-211 — [P1] Start has no timeout and no pending state, so a hung POST /attempts leaves a dead Start button
status: Backlog
url: https://linear.app/tenken/issue/TEN-211/p1-start-has-no-timeout-and-no-pending-state-so-a-hung-post-attempts

**What breaks.** `startServerAttempt` is awaited with no bound and nothing on screen changes while it is in flight. A repeat tap is dropped by a ref, so the candidate presses Start and nothing happens, forever.

**Evidence.**
`apps/web/app/exam/page.tsx:710-724`:

```ts
if (startingRef.current) return; // ignore double-clicks mid-await
startingRef.current = true;
try {
  let serverId: string | null;
  try {
    serverId = await startServerAttempt(cfg.locale);
```

`startServerAttempt` -> `createServerAttempt` -> `postJson` (`apps/web/lib/data/persistence.ts:155-168`) passes no signal and no timeout. `PillCTA` (`components/ui/PillCTA.tsx:29`) takes only href/onClick/disabled/children, so there is no busy rendering. The same file already timeboxes the deck fetch 370 lines earlier: `withTimeout(fetchHostedTrackConfig(...), CONTENT_FETCH_TIMEOUT_MS)` (`page.tsx:342`).

**Blast radius.** Every hosted candidate, at the first action of the sitting, whenever the first request hits a cold instance behind a dead socket.

**Fixed when.** The create is wrapped in `withTimeout` (the copy already exists, `startFailureCopy` at `page.tsx:103`), the pill renders a pending state, and a fake-timer test asserts the failure copy appears after the bound.
