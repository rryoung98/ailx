# TEN-218 — [P1] A hung mirror POST blocks flush() for ever, so the T1 site upload never starts
status: Backlog
url: https://linear.app/tenken/issue/TEN-218/p1-a-hung-mirror-post-blocks-flush-for-ever-so-the-t1-site-upload

**What breaks.** The T1 upload awaits `flush()`, which returns the serialized sync chain. Because mirror requests have no timeout, one request that hangs rather than fails never settles the chain, and the upload never begins.

**Evidence.**
`apps/web/lib/data/siteUpload.ts:314-319`:

```ts
return getAttemptPersistence().flush().then(() => uploadSiteZip(storage, opts, clientAttemptId, zip));
```

`flush()` returns `this.inflight` (`lib/data/persistence.ts:199-201`), fed by `postJson` with no timeout and no signal (`persistence.ts:155-168`). The exam page then sits in `{ state: "uploading" }` (`app/exam/page.tsx:393-404`) and `SiteUploadNotice` offers a retry only in the error state.

**Blast radius.** Every hosted T1 completion behind a stalled connection. The candidate finishes the build they just made and the publish never ends and cannot be retried.

**Fixed when.** `flush()` is bounded, or the upload does not await it unboundedly, and a test with a never-settling fetch asserts a visible error with a retry.
