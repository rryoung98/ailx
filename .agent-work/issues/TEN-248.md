# TEN-248 — [P1] The startup probe reads /livez, so a misconfigured revision goes green and takes all traffic
status: Backlog
url: https://linear.app/tenken/issue/TEN-248/p1-the-startup-probe-reads-livez-so-a-misconfigured-revision-goes

**What breaks.** The README claims the service refuses to start when `AILX_AUTH` is unset. It does not. `server.ts` binds the port first, and the pool, the auth provider, the snapshot store and the instrument are all lazy `??=`. The Cloud Run startup probe and the deploy smoke test both read `/livez`, which returns a JSON literal and touches nothing. `/readyz` does check Postgres and the bank and is used by neither. A revision with a broken config passes the probe, takes 100% of traffic, and `release.sh` has no rollback step.

**Evidence.**

* `README.md:337` claims an unset `AILX_AUTH` refuses to start.
* `services/api/src/server.ts:21-24` binds the port before any dependency is constructed. Lazy initialisation at `services/api/src/context.ts:116` and `:189`, `snapshots.ts:114`, `instrument.ts:34`.
* `services/api/src/app.ts:321` `/livez` returns a JSON literal.
* `infra/terraform/run.tf` `startup_probe` and `infra/cloudbuild/release.sh` both use `/livez`.
* MEASURED live: `/readyz` median 93 ms vs `/livez` 67 ms. The cost of using the correct probe is 26 ms.
* `infra/cloudbuild/release.sh` writes only the image and contains no rollback step.

**Blast radius.** Any deploy with a missing or wrong environment variable. The bad revision serves every request and the first symptom is a candidate's 500.

**How we know it is fixed.** The startup probe and the deploy smoke test read `/readyz`, and a revision deployed with `AILX_AUTH` unset fails to become ready instead of taking traffic.
