# TEN-191 — [P1] Every live score manifest is pulled and parsed on three pages with no limit
status: Backlog
url: https://linear.app/tenken/issue/TEN-191/p1-every-live-score-manifest-is-pulled-and-parsed-on-three-pages-with

**What breaks.** `SCORE_MANIFESTS_SQL` (`lib/truth.ts:72`) selects `attempt_id, model_manifest` for every row with `superseded_by IS NULL`, ordered, unbounded. `loadScoreManifests` runs on `/` (`app/(dashboard)/page.tsx:70`), `/truth` and `/money`, all `force-dynamic`. Each manifest is a JSON blob parsed per row per render in `lib/manifest.ts`.

**Evidence.** `lib/truth.ts:72`, `lib/server/read.ts` `loadScoreManifests`, and the three page call sites. One live row today, so nothing shows yet.

**Blast radius.** The overview is the first page opened and it degrades in proportion to success.

**How to know it is fixed.** The arithmetic is aggregated in SQL, or the read carries a LIMIT and the page says in words that it counted the most recent N. Seed 50k rows and hold the read inside a fixed budget.
