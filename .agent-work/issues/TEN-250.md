# TEN-250 — [P2] The T1 snapshot bucket has no versioning and the runtime service account can delete evidence
status: Backlog
url: https://linear.app/tenken/issue/TEN-250/p2-the-t1-snapshot-bucket-has-no-versioning-and-the-runtime-service

**What breaks.** T1 snapshots are the stored input a T1 score is replayed from. The bucket has no object versioning, no retention policy and no lifecycle rule, and the runtime service account holds `objectAdmin`, which includes delete. Byte-identical replay is therefore not enforced in storage: a bug or a compromise removes the evidence with no backstop.

**Evidence.**

* `infra/terraform/storage.tf` is 24 lines and declares no `versioning`, no `retention_policy` and no `lifecycle_rule`. `grep -rn versioning infra/terraform/*.tf` returns nothing.
* The runtime service account binding on the bucket is `roles/storage.objectAdmin`.
* README section 2 invariant: "A T1 snapshot is servable only while a `responses` row records its digest". That gate stops an orphan being served; it does not stop the bytes being deleted while the row remains.

**Blast radius.** Any T1 score whose snapshot is deleted becomes unreplayable, and the `responses` row still claims the digest.

**How we know it is fixed.** The bucket has versioning plus a retention policy, and the runtime SA holds `objectCreator` + `objectViewer` rather than `objectAdmin`.
