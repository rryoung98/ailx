# TEN-226 — [P1] The database dependency ban is a six-name list that omits the documented Neon driver
status: Backlog
url: https://linear.app/tenken/issue/TEN-226/p1-the-database-dependency-ban-is-a-six-name-list-that-omits-the

**What breaks.** The frontend-only gate bans database access by package name. `@neondatabase/serverless` is not on the list, although docs/DEPLOY.md names Neon as the hosted database. Adding it to `apps/web` would put a database client in the public frontend with the whole suite green. The `db/` directory check is also root-only, so `apps/web/db/` passes.

**Evidence.**
`packages/core/test/frontendOnly.test.ts:99`:

```ts
const banned = ["pg", "@types/pg", "@ailx/backend", "@ailx/instrument", "node-pg-migrate", "@clerk/backend"];
```

and the source check at `:157` is `expect(src).not.toMatch(/\bfrom\s+["']pg["']/)`, a single package spelling. Verified by reading the test.

**Blast radius.** The repository split in AGENTS.md, which is enforced by this one test. A plausible innocent change (a hosted page reading Neon directly) breaks the split with no failure.

**Fixed when.** The ban is a rule about capability, not a name list: any dependency matching a known SQL or driver set, plus a per-app `db/` check, and a test that adds `@neondatabase/serverless` to `apps/web/package.json` in a fixture and asserts the gate fails.
