# TEN-182 — [P0] The pg pool has no connect timeout, so an unreachable store hangs every page
status: Backlog
url: https://linear.app/tenken/issue/TEN-182/p0-the-pg-pool-has-no-connect-timeout-so-an-unreachable-store-hangs

**What breaks.** `lib/server/db.ts:30` builds the pool with `max`, `idleTimeoutMillis` and `statement_timeout`, and no `connectionTimeoutMillis`. pg defaults that to 0, which means wait forever. `statement_timeout` only applies once a connection exists, so it guards nothing here. `await getPool(url).connect()` at `lib/server/db.ts:64` is an unbounded await on every page.

**Evidence.** `lib/server/db.ts:26-33` and `:64`. The catch at `:65` holds the honest "the exam database could not be reached" state and never runs while the connect is pending. Best fit for the 95 second hang already observed: the OS TCP timer, not ours, ends the wait.

**Blast radius.** Every dashboard page and both board API routes. The failure is a hang, so the empty-state vocabulary never gets to speak.

**How to know it is fixed.** `connectionTimeoutMillis` set to a few seconds. Point the URL at an unrouteable address (not a closed port, which fails fast), load `/kpi`, assert the error state renders inside the deadline.
