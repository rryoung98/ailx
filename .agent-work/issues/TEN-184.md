# TEN-184 — [P1] A hung board read pins the in-flight promise for the life of the process
status: Backlog
url: https://linear.app/tenken/issue/TEN-184/p1-a-hung-board-read-pins-the-in-flight-promise-for-the-life-of-the

**What breaks.** `lib/server/boardCache.ts:44-52` stores the in-flight promise and clears it only in `finally`. A read that never settles is never cleared, so every later `/board` render and every 60 second `/api/board` poll joins the same dead promise. The board stays down until redeploy.

**Evidence.** `lib/server/boardCache.ts:41-52`, together with the missing abort signal at `lib/linearBoard.ts:190`.

**Blast radius.** `/board` and both board routes, for every reader, until the instance restarts.

**How to know it is fixed.** After a never-resolving read, the next call starts a fresh read. A stub that hangs once and then answers must produce an answer on the second call.
