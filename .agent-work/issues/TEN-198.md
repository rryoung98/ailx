# TEN-198 — [P2] Nothing in the types stops a rate being taken across the funnel and cohort seam
status: Backlog
url: https://linear.app/tenken/issue/TEN-198/p2-nothing-in-the-types-stops-a-rate-being-taken-across-the-funnel-and

**What breaks.** The seam is the page's strongest claim and it is held by prose and review only. `SEAM_WORDS` states it, the panels obey it, and nothing enforces it.

**Evidence.** `features/analytics/model.ts` defines `FrontFunnelCounts` (browsing sessions, browsers, rounds) and `FunnelCounts` (participants, sittings) as plain `number` fields. `lib/measured.ts` `ratio()` takes two bare numbers. Any future call site can divide a session count by a sitting count and the type checker, the lint run and the test suite all pass. The one structural protection, that `funnel_events` carries no participant or attempt id, lives in the exam service and not here.

**Blast radius.** One careless panel and the dashboard publishes a conversion rate with no defensible denominator, which is the exact error `docs/SAMPLING.md` says the two-track design exists to prevent.

**How to know it is fixed.** The two units are distinct types (branded numbers or wrapper types) so a cross-unit ratio does not compile, or a test asserts every `ratio()` call site takes both arguments from the same count object.
