# TEN-238 — [P0] Judging is disabled in every committed environment, so no sitting can ever receive a T3 score or a composite
status: In Review
url: https://linear.app/tenken/issue/TEN-238/p0-judging-is-disabled-in-every-committed-environment-so-no-sitting

**What breaks.** `judge_enabled` is false in both tfvars and in the variable default, and all of `judging.tf` is count-gated on it. So no judge Cloud Run Job, no Cloud Scheduler and no judge service account exist anywhere, and the service receives no `AILX_JUDGE_*` env. Every finalized T1 or T3 track ends terminal `unscored` / `judging_failed` with reason `unconfigured`. The composite requires all three scored tracks, so no candidate can be issued a composite at all. This is the same shape as the known no-caller defect: the fix shipped in code and not in deployment.

**Evidence.**

* `infra/terraform/env/staging.tfvars:55` `judge_enabled = false`; `infra/terraform/env/resilient-staging.tfvars:49` the same; `infra/terraform/variables.tf:310` default `false`.
* `infra/terraform/judging.tf` gates the job, the scheduler and the SA on that variable.
* `packages/backend/src/judging/*` refuses with `unconfigured` when `AILX_JUDGE_BASE_URL` is unset (README section 6.1), and `packages/backend/src/scoresOfRecord.ts` turns that into a terminal `judging_failed`.
* README section 5.2: the composite is withheld unless all three scored tracks have a score of record.
* Live: `judging_runs` is empty on the production database.
* The in-process kick (`services/api/src/judging.ts`) is detached work under `cpu_idle = true` and `min_instances = 0`, so it is not a substitute for the scheduler.

**Blast radius.** Every hosted candidate. T2 gets a number; T1 and T3 never do; the composite is never issued.

**How we know it is fixed.** `judge_enabled = true` in the environment the frontend points at, the Cloud Run Job and scheduler exist, and a finalized sitting reaches `state: scored` for T3 without an operator running anything by hand.
