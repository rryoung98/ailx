# TEN-239 — [P1] The finalize judging kick takes a second pool client and holds it across the whole jury run
status: In Review
url: https://linear.app/tenken/issue/TEN-239/p1-the-finalize-judging-kick-takes-a-second-pool-client-and-holds-it

**What breaks.** `handleFinalize` awaits the judging kick while the request still holds its own pool client, and the kick checks out a SECOND client and keeps it through every model call. With the default pool of 3, three concurrent finalizes deadlock on the second checkout; with pool 8, eight do. This is the first thing that falls over under real load, and it takes down candidates who are still mid-sitting on the same instance.

**Evidence.**

* `packages/backend/src/handlers.ts:642-655` awaits `ctx.judging.kick` on `ctx.db` with no `offConnection`.
* `services/api/src/judging.ts:99-118` `run()`: `const { db, release } = await checkout()` ... `await drainJudgingQueue(deps, 1)` ... `finally { release() }`. The client is released only after the whole pass.
* `services/api/src/context.ts:112` `DEFAULT_POOL_MAX = 3`; `context.ts:106-107` `connectionTimeoutMillis: 10_000`.
* `packages/backend/src/judging/model.ts:125` `timeoutMs: 120_000, maxRetries: 2`. One jury member is up to 3 x 120 s on that held connection.
* The repo already enforces this exact rule elsewhere: `packages/backend/src/lease.ts:1-33` and the `guardHeld` port wrapper at `lease.ts:203`. The judge client is not a guarded port.
* `packages/backend/src/judging/runner.ts` header claims "IT HOLDS NO POOL CLIENT WHILE A MODEL IS SPEAKING". That is true of the request's client only.

**Blast radius.** Every route on the affected instance, including `POST /responses` inside a live sitting. Cloud Run queues rather than sheds, so the failure is a 500 after the 10 s acquire timeout.

**How we know it is fixed.** The judging pass uses its own pool or a fresh client, or releases around each model call. A load test of N concurrent finalizes shows request latency flat while the passes run.

*Filed from a read-only review of* `ailx-backend` *@* `72db4e6` *(main), 2026-09-07.*
