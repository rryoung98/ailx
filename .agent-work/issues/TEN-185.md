# TEN-185 — [P1] The pg pool has no error listener, so one idle client reset can end the process
status: Backlog
url: https://linear.app/tenken/issue/TEN-185/p1-the-pg-pool-has-no-error-listener-so-one-idle-client-reset-can-end

**What breaks.** There is no `pool.on("error", ...)` anywhere. pg re-emits an idle client's error on the Pool, and an EventEmitter with no `error` listener throws, which in the Next server is an uncaught exception.

**Evidence.** `lib/server/db.ts:26-33`; a grep for `pool.on` over `lib`, `app` and `features` is empty. Managed Postgres reaping idle sessions, a failover, or a NAT idle drop all trigger it. `idleTimeoutMillis: 10_000` narrows the window and does not close it.

**Blast radius.** The whole dashboard, every reader, until the platform restarts the instance.

**How to know it is fixed.** A listener that logs and does nothing else. Against a throwaway local Postgres: check a client in, terminate its backend, assert the process survives and the next `readRows` answers.
