# TEN-255 — [P2] AILX_REVIEWERS is set by no deployment, so no share carrying a site or a note can ever be listed
status: Backlog
url: https://linear.app/tenken/issue/TEN-255/p2-ailx-reviewers-is-set-by-no-deployment-so-no-share-carrying-a-site

**What breaks.** A share that carries a T1 site or a candidate note needs a human stamp before it is listed. The reviewer allowlist is an environment variable that no deployment sets, and there is no Terraform variable for it, so `isReviewer` is false for everybody and the queue can never be worked. Appeals in the moderation thread can never be answered either.

**Evidence.**

* `packages/backend/src/gallery.ts` `REVIEWERS_ENV = "AILX_REVIEWERS"`; `reviewerRefs` fails closed on unset; `gallery.ts:556-568` `withReviewer` returns 403 to everyone.
* `grep -rn AILX_REVIEWERS` finds only `README.md`, tests and `gallery.ts`. It is absent from `infra/terraform/run.tf` `runtime_env` and there is no variable for it in `variables.tf`.
* `packages/contract/src/share.ts` `needsHumanApproval(payload)` returns true when `site !== null` OR `note !== null`; `packages/backend/src/share.ts` `publishShare` auto-stamps only when `!needsHumanApproval`.
* `services/api/src/app.ts:502-505` registers the review routes regardless.

Two more variables the code reads that no deployment sets: `AILX_INSTRUMENT_DIGEST` (unset makes the digest pin a no-op, `packages/instrument/src/index.ts:255-260`) and `AILX_TRUST_PROXY` (unset makes the per-address anonymous rate limit inert, `services/api/src/rateLimit.ts` `clientAddress`).

**Blast radius.** Every candidate who opts their build or their note into the gallery. They see `submitted`, for ever, with no reviewer able to exist.

**How we know it is fixed.** `AILX_REVIEWERS` is a Terraform variable wired into `runtime_env`, at least one deployed environment names a reviewer, and `GET /v1/gallery/review` returns 200 for that identity.
