# TEN-222 — [P1] The landing hero fades its drill and both CTAs to opacity 0 but leaves them clickable and in the tab order
status: Backlog
url: https://linear.app/tenken/issue/TEN-222/p1-the-landing-hero-fades-its-drill-and-both-ctas-to-opacity-0-but

**What breaks.** The hero fade animates opacity only, with no `visibility`, `pointer-events: none` or `inert`. The stage is a sticky 100vh block inside a 185vh scrubber, so the invisible drill and both call-to-action links stay parked over the viewport for the rest of the pin and stay focusable.

**Evidence.**
`apps/web/app/page.tsx:243-249`:

```tsx
<div className="hero-fade hero-play" data-pill-clear=""><PracticeDrill taster /></div>
<p className="hero-cta hero-fade" data-pill-clear="">
  <Link className="btn primary" href="/practice">Play a full round</Link>
  <Link className="btn" href="/exam">Go for the credential</Link>
```

`apps/web/app/globals.css:849-854, 913-916` (`heroFadeOut` ends at `opacity: 0` only); the stage is `position: sticky; height: 100vh` at `:831-833`, and `.hero-stage` repeats the omission in `heroSettle` (`:836-838`). The same stylesheet gets it right elsewhere: the campus-card keyframes use `visibility: hidden`.

**Blast radius.** The landing page in every browser with scroll-driven animations, which is the majority path. A keyboard user tabs into two invisible CTAs and a pair of invisible drill buttons with no visible focus ring (WCAG 2.4.7, 2.4.11); a touch user can answer a card they cannot see.

**Fixed when.** The fade keyframes carry `visibility: hidden` at the final stop, or the block is `inert`, and a test asserts a `.hero-fade` control is not focusable once the fade has completed.
