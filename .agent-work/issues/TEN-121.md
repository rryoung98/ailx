# TEN-121 — The static build's footer says "No network calls" while the same build sends exam prompts to a third party
status: Backlog
url: https://linear.app/tenken/issue/TEN-121/the-static-builds-footer-says-no-network-calls-while-the-same-build

`apps/web/lib/mode.ts:36-45`, rendered on every page by `app/layout.tsx:92`:

> "static demo build. Every model call is a deterministic simulator, seeded by SHA-256 of its inputs. **No network calls. Everything runs in your browser.**"

Two things in the same build contradict it:

1. `features/exam/ConnectPanel.tsx:61` `SHARED_DEMO_BASE_URL = "https://ailx-shared-demo.vercel.app/api/v1"`, actively recommended by `STATIC_NO_KEY_COPY` (`:89`). A candidate who accepts sends their **T1 prompts, T1 HTML and T4 direction notes** to a third-party origin. `packages/tracks/t1-creative-build/src/Runner.tsx:226` then makes real calls.
2. `app/wall/page.tsx:50,57` and `app/report/page.tsx:96` hit the same third party.

This is a privacy claim. The comment directly above the function records that a dogfooder caught the identical lie in the hosted build; only the hosted half was fixed. `apps/web/test/mode.test.tsx:36,65` now **pin the false sentence**.

Do: condition the clause on real state - say the simulator is the default and runs locally, and name the origin when `ailx:llm-base-url` is set to a non-localhost endpoint. Update the pinning tests.
