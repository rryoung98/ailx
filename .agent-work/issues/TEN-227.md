# TEN-227 — [P1] @clerk/backend is banned by declared name but reachable through @clerk/nextjs/server
status: Backlog
url: https://linear.app/tenken/issue/TEN-227/p1-clerkbackend-is-banned-by-declared-name-but-reachable-through

**What breaks.** The gate bans `@clerk/backend` as a declared dependency. `@clerk/nextjs@7.8.4` ships it transitively, so `import { auth } from '@clerk/nextjs/server'` puts token verification in this repo, one import away, with no test failing. AGENTS.md states this app verifies no token and deliberately holds no `CLERK_SECRET_KEY`.

**Evidence.**
`packages/core/test/frontendOnly.test.ts:99` bans the declared name only. Transitive presence confirmed on disk: `ls node_modules/.pnpm | rg clerk` shows `@clerk+backend@3.16.13` and `@clerk+backend@3.17.0` alongside `@clerk+nextjs@7.8.4`. No test greps for `@clerk/nextjs/server` (`rg -n '@clerk/nextjs/server' packages/core/test` returns nothing).

**Blast radius.** The auth boundary. A hosted `page.api.tsx` that verifies a token here would duplicate the exam service's only security decision, and the split test would stay green.

**Fixed when.** The gate greps sources for `@clerk/nextjs/server` and any `@clerk/backend` import path, not just the manifest, with a fixture asserting the failure.
