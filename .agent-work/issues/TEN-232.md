# TEN-232 — [P2] Time with the browser closed or asleep is charged to the track budget, while the copy says only working time is charged
status: Backlog
url: https://linear.app/tenken/issue/TEN-232/p2-time-with-the-browser-closed-or-asleep-is-charged-to-the-track

**What breaks.** The budget is pure wall clock from `runningSince`, and nothing pauses it on unload. A laptop that sleeps or a browser killed by the OS returns to a track that is already over, which contradicts what the app tells the candidate.

**Evidence.**
`packages/session/src/machine.ts:198`:

```ts
const running = t.runningSince !== undefined ? Math.max(0, nowMs - t.runningSince) : 0;
return t.activeMs + running;
```

No `beforeunload` or `pagehide` pause exists in `apps/web/app/exam/page.tsx` (the unload-adjacent listeners at `:238-240` only re-read the model connection). The copy at `page.tsx:1091`: `Only working time is charged.`

**Blast radius.** Any candidate with a crash, a forced restart or a sleeping machine mid-track. It is the same fairness rule the crash boundary and the content hold already honour.

**Fixed when.** The page records a `paused` entry on `pagehide` and the resume path decides explicitly what an unattended gap costs, with a test.
