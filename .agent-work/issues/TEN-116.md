# TEN-116 — A hosted deck fetch that hangs or fails burns the whole track budget and reports the zero as "you were working"
status: Backlog
url: https://linear.app/tenken/issue/TEN-116/a-hosted-deck-fetch-that-hangs-or-fails-burns-the-whole-track-budget

`apps/web/app/exam/page.tsx:244-268` (deck fetch), `:393-416` (watchdog), `:906-936` (TimeUpNotice).

`track_started` is committed by the Start button, so the clock runs; only then does the deck fetch begin. Neither the "Loading your deck..." state nor the deck-error state pauses the clock. The watchdog then fires and scores an empty artifact.

Reproduced with `fetchHostedTrackConfig` mocked to hang and to reject(503), 30s budget - both end:
`track_started:t2 -> track_completed:t2(timedOut=true) -> track_scored:t2(scaled=0)`
and render "the clock ran out **while you were working** ... **your work was kept**". The candidate never saw an item. Both sentences are false on this path.

This is our fault charged to a non-revisitable budget. The page already has the right pattern for our faults: a runner crash pauses the clock (`:438-460`). The "Loading track runner..." dynamic import is charged the same way.

Do: pause the clock while the deck/runner is not yet presentable, and give the fetch a timeout with a visible failure state.
