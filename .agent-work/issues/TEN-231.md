# TEN-231 — [P2] T2's fixed exposure window is counted in interval ticks, so a background tab stretches it in wall-clock time
status: Backlog
url: https://linear.app/tenken/issue/TEN-231/p2-t2s-fixed-exposure-window-is-counted-in-interval-ticks-so-a

**What breaks.** The exposure countdown is a one-second `setInterval`. Browsers throttle background-tab intervals to roughly one tick a minute, so an item's exposure is measured in ticks the tab was allowed to run, not in seconds of exposure. The decision latency beside it is wall clock, so the two disagree.

**Evidence.**
`packages/tracks/t2-discrimination/src/Runner.tsx:426`:

```ts
setSecondsLeft(exposure);
const t = setInterval(() => {
  if (choiceRef.current !== null || pausedRef.current) return;
  setSecondsLeft((s) => (s === null ? null : s - 1));
}, 1000);
```

The lapse fires off `secondsLeft` (`:441`), while `shownAt.current = performance.now()` (`:420`) is wall clock.

**Blast radius.** T2 exposure is a controlled measurement condition, so this is a comparability defect across candidates, not a crash. A candidate who switches tabs silently gets a longer look while the track budget keeps running.

**Fixed when.** Remaining exposure is derived from `performance.now()` deltas, with a test that advances time without advancing timers.
