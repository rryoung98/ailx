# TEN-203 — [P2] The client import graph guard is a regex walk with three holes
status: Backlog
url: https://linear.app/tenken/issue/TEN-203/p2-the-client-import-graph-guard-is-a-regex-walk-with-three-holes

**What breaks.** The test that proves the identity module never reaches a client bundle does not resolve a real import graph.

**Evidence.** `test/identitySecrecy.test.ts`: entry points are files whose text `startsWith('"use client"')` (`:76`), so a client file starting with a comment, a BOM or single quotes is not an entry at all; `importsOf` (`:57`) matches only `from "..."`, so a bare side-effect import, a dynamic `import(...)` and `next/dynamic` are invisible; the scanned roots (`:36`) omit `hooks/`. The bundle half greps for key values and one log sentence, not for `CLERK_API_ROOT` or `resolveClerkUser`, so a bundled but key-less identity module would pass. `test/boardSecrecy.test.ts` has the same shape.

**Blast radius.** The guard holds today, and `import "server-only"` is the real backstop, which is why this is P2. The risk is that the guard is trusted for a property it does not check.

**How to know it is fixed.** The graph is resolved with the bundler's own resolution or a real parser, `hooks/` is scanned, and adding a dynamic import of the identity module into a client file makes the test fail.
