# TEN-111 — HIGH: the T1 upload path can OOM a Cloud Run instance — 25MB double-buffered, no rate limit, 512Mi at concurrency 80
status: Backlog
url: https://linear.app/tenken/issue/TEN-111/high-the-t1-upload-path-can-oom-a-cloud-run-instance-25mb-double

From the 2026-09-04 backend review (/Users/rickyyoung/GitHub/ailx-backend-review-2026-09-04.md, finding **D2**, BUG/HIGH).

* `services/api/src/context.ts:42-43` — `MAX_RAW_BODY_BYTES = T1_LIMITS.maxTotalBytes` = 25 MB.
* `services/api/src/context.ts:130-160` — `readCappedBody` buffers every chunk in `chunks[]` then copies into `out`: transiently TWO copies of the body.
* `services/api/src/app.ts:341-352` — `POST /v1/attempts/:id/site` is `{ rawBody: true }` with **no** `limit`. `services/api/src/rateLimit.ts` covers only score/finalize and the model routes.
* `infra/terraform/variables.tf:129` memory default `512Mi` (not overridden in `env/staging.tfvars`), `:164` concurrency default `80`, `:153` max_instances 4.

**Measured** against the repo's own `packages/backend/dist/t1/snapshot.js` with 21 stored/incompressible files totalling 24 MB: baseline 66 MB rss; 1 upload in flight 178 MB; 4 in flight 307 MB — roughly 46 MB retained per in-flight upload. About 8-9 concurrent uploads OOM-kill an instance, taking every other in-flight sitting on it with it. `GET /v1/attempts/:id/site/export` has the same shape: it repacks a whole ZIP in memory.

**Fix.** Rate-limit `POST /v1/attempts/:id/site` per identity (it is the only unlimited rawBody route), set an explicit memory value well above 512Mi for the upload path, and lower concurrency or stream the body to the snapshot store instead of double-buffering.
