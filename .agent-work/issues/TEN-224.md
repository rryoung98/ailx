# TEN-224 — [P1] Exam phase changes never move focus to the new view while the clock runs
status: Backlog
url: https://linear.app/tenken/issue/TEN-224/p1-exam-phase-changes-never-move-focus-to-the-new-view-while-the-clock

**What breaks.** The exam page renders five whole-page phases from one component and only the time-up notice lands focus. A screen-reader candidate presses Start, hears nothing, and has to tab from the top of the document to find out whether the track opened. That time is charged to them.

**Evidence.**
`apps/web/app/exam/page.tsx`: `:1062-1065` `TimeUpNotice` does it right (`useEffect(() => { headingRef.current?.focus(); }, [])`). No focus move on start pill to runner (`:702`), between-tracks button to runner (`:856-861`), runner to between-tracks (`h1` at `:808`), or to Run complete (`h1` at `:754`). FRONTEND.md section 5: `Phase/route change: move focus to the new view's heading`. Next's App Router focus handling covers route changes, and all of these are in-page.

**Blast radius.** Every scored sitting taken with a screen reader or a keyboard. The clock is already running when the phase swaps, because `track_started` is committed in the same click.

**Fixed when.** Each phase view owns a `tabIndex={-1}` heading focused on entry, like `TimeUpNotice`, with a test per transition asserting `document.activeElement` is the new heading.
