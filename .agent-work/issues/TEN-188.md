# TEN-188 — [P1] The middleware asks Clerk for the user on every request, so normal use can rate limit the dashboard
status: Backlog
url: https://linear.app/tenken/issue/TEN-188/p1-the-middleware-asks-clerk-for-the-user-on-every-request-so-normal

**What breaks.** `middleware.ts:47` calls `users.getUser` on every matched request with no cache. The matcher at `:68` excludes only `_next/static`, `_next/image` and `favicon.ico`, so every RSC navigation payload, every file under `public/`, and every 60 second `/api/board` poll per open tab is one Clerk Backend API call.

**Evidence.** `middleware.ts:47` and `:68`. Clerk BAPI limits are per instance and in the low hundreds per 10 second window. The first 429 lands in the catch at `:38` and renders as a denial, so the failure presents as a lockout that blames the allowlist.

**Blast radius.** The whole app, worse with each tab left open.

**How to know it is fixed.** Memoise the email per user id for 30 to 60 seconds in module scope, the trick `boardCache` already uses, or carry the email in the session claim. Count `getUser` calls across one navigation and assert it is one.
