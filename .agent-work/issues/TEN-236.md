# TEN-236 — [P2] The public-tree gate constrains file names, so a keyed bank under a new instruments directory passes every assertion
status: Backlog
url: https://linear.app/tenken/issue/TEN-236/p2-the-public-tree-gate-constrains-file-names-so-a-keyed-bank-under-a

**What breaks.** The content gate asserts on manifests, rubrics, prompt directories and the snapshot name. A new directory under `instruments/` carrying `bank.jsonl` with keys and no manifest matches none of those patterns and passes. Two unconstrained directories already live there (`practice/`, `characters/`), so this is the shape a mistake would take.

**Evidence.**
`packages/content-tools/test/public-tree.test.ts` matches by manifest and by known file names; there is no assertion of the form every file under `instruments/**` is named by a manifest. Contrast `apps/web/test/bundleSecrecy.test.ts`, which does exactly that for `apps/web/public/**` (the inventory added in <issue id="8915b6f3-cbd0-43e5-97ac-b84e456ef310" href="https://linear.app/tenken/issue/TEN-117/bundlesecrecytestts-cannot-see-appswebpublic-or-any-non-js-file">TEN-117</issue>).

**Blast radius.** The operational bank custody rule in AGENTS.md, which is the reason this repo is public at all. Bundle secrecy would still catch it if the file reached a build output; it would not catch it sitting in the tree of a public repo.

**Fixed when.** The content gate carries an inventory: every file under `instruments/**` is named by a committed manifest or by a frozen list, with a fixture proving an unmanifested `bank.jsonl` fails.
