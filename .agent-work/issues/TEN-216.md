# TEN-216 — [P1] Only /gallery validates its response body, so a 200 with an unknown shape crashes /progress, /world and /s/<token>
status: Backlog
url: https://linear.app/tenken/issue/TEN-216/p1-only-gallery-validates-its-response-body-so-a-200-with-an-unknown

**What breaks.** Two response schemas exist and exactly one call site uses one. Every other page casts the body and dereferences it during render, so any wire-shape drift between the private service and this repo throws a TypeError into the root error boundary instead of the sentence written for that case.

**Evidence.**
`packages/contract/src/tables.ts:49-52` defines `API_RESPONSE_SCHEMAS` with `gallery` and `profile` only; `rg -n 'schema:' apps/web --glob '!*.test.*'` finds one call site, `features/gallery/GalleryView.tsx:127`. Unchecked casts: `features/progress/ProgressView.tsx:356-357`, `features/world/WorldView.tsx:122,145`, `features/share/ShareView.tsx:62-63`, `app/s/[token]/card.png/route.api.ts`. `lib/data/serviceFetch.ts:188` is explicit: `if (opts.schema === undefined) return { state: "ready", data: body as T };`. The mechanism works where it is used: `apps/web/test/galleryPage.test.tsx:397-439`.

**Blast radius.** Any deploy skew between the two repos, which AGENTS.md guarantees deploy on separate clocks. The candidate or the stranger lands on `Something broke on this screen` with a `Back to your run` button that means nothing on /verify or /s/<token>. `SERVICE_INVALID_COPY` (`serviceFetch.ts:89-90`) is never shown.

**Fixed when.** `progress`, `aggregates`, `shareView` and `credentialView` have schemas, the four call sites pass them, and each page has a test that feeds a 200 with a missing key and asserts `SERVICE_INVALID_COPY` instead of a throw.
