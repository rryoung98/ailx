# TEN-201 — [P2] The who parameter is not validated as a uuid, so a typo reads as a database failure
status: Backlog
url: https://linear.app/tenken/issue/TEN-201/p2-the-who-parameter-is-not-validated-as-a-uuid-so-a-typo-reads-as-a

**What breaks.** `features/people/model.ts:408` only trims and truncates `who`. `PARTICIPANT_AUTH_REF_SQL` casts `$1::uuid`, so a non-uuid makes Postgres raise, and the page prints "the exam database refused the query".

**Evidence.** `features/people/model.ts:408`, `features/people/sql.ts` `PARTICIPANT_AUTH_REF_SQL`. The surrounding comment says a hand-edited URL is not a fault condition, which is right and is not what happens here.

**Blast radius.** `/people?who=` with any typo. The store is blamed for a URL.

**How to know it is fixed.** The uuid shape is checked in `parsePeopleQuery` and the existing "no participant carries that id" sentence renders instead. One unit test with `?who=nope`.
