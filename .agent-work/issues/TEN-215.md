# TEN-215 — [P1] The credential and share panels read before identity arrives and never re-read, so a candidate who holds a credential is offered a fresh one
status: Backlog
url: https://linear.app/tenken/issue/TEN-215/p1-the-credential-and-share-panels-read-before-identity-arrives-and

**What breaks.** Both panels fire their read on mount, with no identity gate and no re-read. In the pre-bridge window the read carries no token, the service answers 401, `held` becomes null and the panel renders the OFFER. The candidate is told nothing exists yet, and the Revoke control is not on screen. The share panel shows the create form instead of the existing unlisted link.

**Evidence.**
`apps/web/features/report/CredentialPanel.tsx:101-126`:

```ts
const held = res.ok ? ownerCredential(await res.json()) : null;
if (held === null) { setPhase("none"); return; }
```

`request` is `useCallback(..., [attemptId])` (`:86-99`), so the effect never re-runs on identity. `features/report/ShareLink.tsx:208-232` is the same code with `[attemptId, request]`. Neither file imports `useIdentity`; both call `browserApiOptions().fetchFn` directly, bypassing `useService`. The repo already fixed this class for the sibling read: `features/report/useScoresOfRecord.ts:67-75` documents it and `apps/web/test/scoresOfRecord.test.tsx:412` pins it (<issue id="461bbf06-f5cc-4f7f-9bc2-9020749b04d7" href="https://linear.app/tenken/issue/TEN-152/scores-of-record-never-load-for-a-signed-in-candidate-the-reports">TEN-152</issue>). `rg -n 'identity' apps/web/test/credentialSurface.test.tsx apps/web/test/shareLink.test.tsx` returns nothing. Both panels mount as soon as the LOCAL log says finished (`app/report/page.tsx:306-311`, `reportGate.ts:74`), before any service answer.

**Blast radius.** Every returning candidate on a Clerk deployment, on every load of /report, and worse on a slow connection. A false sentence plus a lost revoke path on the credential surface.

**Fixed when.** Both panels gate on `useIdentity().status !== "pending"` or go through `useService`, and a test mounts each with identity pending, publishes a signed-in identity, and asserts the read happens once, after the publish.
