# TEN-223 — [P1] Answering a practice card or a daily card drops focus onto <body>
status: Backlog
url: https://linear.app/tenken/issue/TEN-223/p1-answering-a-practice-card-or-a-daily-card-drops-focus-onto-body

**What breaks.** The answer handler unmounts the button the user just pressed and recovers no focus. The same is true of the Next control. Focus falls to the document, so a keyboard or screen-reader user tabs through the skip link, the wordmark and eight nav links to get back, twice per card.

**Evidence.**
`apps/web/features/practice/PracticeDrill.tsx:318-346` `answer()` sets `setPhase("feedback")` and never calls `setRecoverFocus(true)`, while `drop()` (`:351`) and `retryStimulus()` (`:359`) both do; `next()` (`:431`) has the same gap. Daily: `features/daily/DailyChallenge.tsx:252` and `:277`, which only moves focus on `justFinished` (`:101-105`). This is a known P0 already fixed for the scored T2 runner: `apps/web/e2e/t2-keyboard.spec.ts:20` calls it `the dogfood P0`, and FRONTEND.md section 5 states the rule. Existing coverage is the skip path only (`apps/web/test/practiceDrill.test.tsx:411`).

**Blast radius.** The practice drill (its own page and the landing hero taster) and the daily challenge, in both build modes. These are the two highest-traffic playable surfaces and the first thing a stranger touches.

**Fixed when.** `answer()` and `next()` use the same focus recovery as `drop()`, and the practice and daily tests assert `document.activeElement` stays inside the stage after a call and after Next card.
