# TEN-219 — [P1] Checkpoint write failures are swallowed, and the timeout watchdog then scores the stale checkpoint
status: Backlog
url: https://linear.app/tenken/issue/TEN-219/p1-checkpoint-write-failures-are-swallowed-and-the-timeout-watchdog

**What breaks.** `saveCheckpoint` swallows quota and security errors on the argument that the log still holds completed artifacts. That is true only for a completed track. For a running one the checkpoint IS the artifact of record on timeout, so a candidate whose later checkpoints silently failed is scored on the last one that fit.

**Evidence.**
`apps/web/lib/data/checkpoints.ts:42`:

```ts
try {
  storage.setItem(checkpointKey(attemptId, trackId), JSON.stringify(shape));
} catch {
  // Quota exceeded / private mode: the log still holds completed artifacts.
}
```

`apps/web/app/exam/page.tsx:480`:

```ts
const cp = state.attemptId ? loadCheckpoint(window.localStorage, state.attemptId, t) : undefined;
finishTrack(t, checkpointToArtifact(t, cp));
```

`apps/web/test/checkpoints.test.ts:57` pins the swallow. Nothing tests that the candidate is told.

**Blast radius.** T4 and T1 (large payloads) and any private-mode browser. Silent partial loss of scored work, presented as a score.

**Fixed when.** `saveCheckpoint` reports failure to the host, the host raises the persistence banner or holds the clock, and a test asserts a failed checkpoint write is visible.
