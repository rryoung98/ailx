## 3. Definition of done (the reward signal)
Every issue body ends with a "How to know it is fixed" line. That line is the per-issue reward.
The repo gates are the global reward:
1. `pnpm test` (one vitest for the monorepo, worker pool 4)
2. `pnpm -r build` (both build modes)
3. `pnpm lint` (Biome; an error fails, a warning is carried debt)
4. a NEW test that fails before the fix and passes after it (required, per AGENTS.md)

Score for one attempt: 0 if any gate fails, else 1 per issue whose stated criterion is met by a
committed test. No partial credit for "looks right".

## 4. Reinforcement loop
Per batch:
- roll out: a subagent works the batch on its own branch/worktree
- evaluate: run the gates + the per-issue criterion
- reward: pass/fail per issue, plus gate output
- credit assignment: a failed gate becomes a NEW Linear-shaped task with the exact failure
- policy update: the failure text is written back into the next batch prompt, and repeated
  failures become a harness memory so later workers do not repeat them
- recurse: a worker that cannot close an issue spawns its own child for the narrow blocker

Stop conditions: 3 failed rollouts on one batch, or a batch that needs a product decision.
Those escalate to the human queue instead of looping.
